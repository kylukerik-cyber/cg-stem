# cg-stem: відновлення фотографій облич
Аналіз та обробка зображень класичними методами. STEM-проєкт з дисципліни "Комп'ютерна графіка та візуалізація", варіант 2 (два пайплайни).
Усі методи реалізовані через NumPy. Pillow потрібен лише щоб читати і зберігати файли. Штучний інтелект, машинне навчання і функції бібліотек комп'ютерного зору не використовуються.

## Вибірка
120 фотографій облич з набору Labeled Faces in the Wild (LFW, версія funneled), джерело: http://vis-www.cs.umass.edu/lfw/
Обрано 120 різних людей (перше фото кожної, фіксований seed), з кожного фото вирізано центральну ділянку 160x160 з обличчям.
- images/ - 100 зображень для оцінювання;
- tune_images/ - 20 інших зображень, лише для підбору параметрів;
- sources.csv - з якого файлу LFW взято кожне зображення.

Чисті фото штучно спотворюються (5 сценаріїв), а результат обробки порівнюється з чистим фото.

| Сценарій | Що моделює | Параметри |
|---|---|---|
| `gauss_10` | слабкий шум сенсора | гаусів шум, sigma = 10 |
| `gauss_25` | сильний шум сенсора | гаусів шум, sigma = 25 |
| `salt_pepper` | збої пікселів | 5 % пікселів стають 0 або 255 |
| `low_light` | слабке освітлення | I' = 0,7 * 255 * (I / 255)^1,6 + шум sigma = 8 |
| `color_cast` | неправильний баланс білого | R x 1,15, B x 0,8 + шум sigma = 10 |

## Пайплайни
| Пайплайн | Стадія 1 | Стадія 2 | Стадія 3 |
|---|---|---|---|
| `p1` | `bilateral` - білатеральний фільтр (фільтрація) | `clahe` - адаптивне вирівнювання гістограми (гістограмна корекція) | `unsharp` - нерізке маскування (ретушування) |
| `p2` | `gray_world` - баланс білого Gray World (колірна корекція) | `pyramid` - шумозаглушення в лапласіанній піраміді (масштабно-інваріантні методи) | `butterworth` - НЧ-фільтр Баттерворта (перетворення Фур'є) |

p1: прибрати шум зі збереженням меж, підняти локальний контраст (темні фото), повернути різкість.
p2: виправити колір, прибрати дрібний шум на кількох масштабах, згладити залишок шуму в частотній області.

Метрики якості: MSE, PSNR, SSIM (SSIM у гаусовому вікні 11x11, як у Wang et al., 2004).
Для ДПФ використано numpy.fft (загальна математична функція), сам фільтр Баттерворта зроблено вручну.

## Структура проєкту
```
stem.py         методи, пайплайни, шум, метрики, підбір параметрів, меню запуску
config.json     параметри методів, сценаріїв, тест-кейсів і сітки підбору
test_stem.py    автотести методів і пайплайнів
images/         зображення для оцінювання (100)
tune_images/    зображення для підбору параметрів (20)
sources.csv     джерела зображень у LFW
results/        результати (створюється при запуску)
META-USAGE.md   використання ШІ-інструментів
README.md
```

## Запуск
Python 3.10 або новіший.
```
pip install numpy pillow
python stem.py
```
У меню обирається пайплайн 1, пайплайн 2, обидва, один метод або підбір параметрів, потім сценарій спотворення (або всі).
Програма обробляє всі зображення з images/. Пошкоджені й порожні файли пропускаються з повідомленням, сірі та прозорі зображення переводяться в RGB.
Обробка всіх 100 зображень одним пайплайном в одному сценарії займає близько хвилини.

Автотести на зображеннях 1x2 ... 3x3 (очікувані значення пораховано вручну, розрахунок у docstring кожного тесту):
```
python test_stem.py
```
або `python -m pytest test_stem.py`.

## Параметри config.json
| Параметр | Значення | Опис |
|---|---|---|
| seed | 2026 | seed шуму; шум залежить від seed, назви файлу і сценарію, тому завжди однаковий |
| scenarios | див. таблицю вище | сценарії спотворення |
| p1.bilateral | radius 2, sigma_s 2,5, sigma_r_factor 8 | вікно 5x5; sigma_r = 8 * оцінка шуму зображення |
| p1.clahe | tiles 4, clip_limit 1,5, blend 0,8 | 4x4 блоки, обрізання гістограми, частка результату CLAHE |
| p1.unsharp | sigma 1, amount 0,2, threshold 6 | сила підсилення деталей, поріг проти підсилення шуму |
| p2.gray_world | strength 0,5, norm 8 | сила корекції, показник Shades of Gray |
| p2.pyramid | thresholds [3; 1,5; 0] | пороги обрізання для 3 рівнів піраміди |
| p2.butterworth | cutoff 0,4, order 3 | частота зрізу (частка від максимальної), порядок |
| test_cases, min_psnr_gain | див. нижче | тест-кейси для перевірки коректності |
| tuning_grid | | значення, які перебирає підбір параметрів |

Параметри змінюються без правки коду.

## Підбір параметрів
Пункт меню 5. Для кожної стадії по черзі перебирається сітка значень з tuning_grid, інші стадії фіксовані; обирається варіант з найбільшим середнім SSIM на 20 зображеннях з tune_images/ у сценаріях тест-кейсів пайплайна. Два проходи. Повний журнал: results/tuning_p1.csv, results/tuning_p2.csv. Зображення з images/ у підборі не беруть участі.

Найважливіші висновки підбору: для bilateral малий sigma_r_factor (2) майже не прибирає шум (SSIM 0,53 проти 0,78); для pyramid великі пороги розмивають обличчя (SSIM 0,83 проти 0,92); повна корекція gray_world (strength 1) знижує PSNR до 23,1 дБ проти 30,4 дБ при strength 0,5.

## Результати
Для кожного запуску створюється папка results/<пайплайн>_<сценарій>, наприклад results/p1_low_light/:
- <зображення>_0_input.png - спотворене зображення;
- <зображення>_1_bilateral.png, _2_clahe.png, _3_unsharp.png - результат кожної стадії;
- metrics.csv - колонки image, stage, method, mse_in, psnr_in, ssim_in (спотворене проти оригіналу), mse, psnr, ssim (результат стадії проти оригіналу), seconds.

## Порівняння p1 і p2
На скількох зображеннях кращий кожен пайплайн і середня різниця p1 - p2:

| Сценарій | PSNR: p1 / p2 кращий | різниця PSNR, дБ | SSIM: p1 / p2 кращий | різниця SSIM |
|---|---|---|---|---|
| гаусів шум σ=10 | 1 / 99 | -7,12 | 0 / 100 | -0,038 |
| гаусів шум σ=25 | 1 / 99 | -4,94 | 52 / 48 | -0,001 |
| «сіль і перець» 5 % | 0 / 100 | -6,34 | 0 / 100 | -0,133 |
| слабке освітлення | 100 / 0 | 3,80 | 100 / 0 | 0,156 |
| колірний відтінок | 0 / 100 | -9,49 | 0 / 100 | -0,046 |

Висновки:

p2 кращий за шуму і неправильного кольору: за гаусового шуму sigma = 25 PSNR зростає на 7,6 дБ, за шуму «сіль і перець» на 8,0 дБ, за колірного відтінку на 8,0 дБ.

p1 - єдиний пайплайн, що справляється зі слабким освітленням (+3,7 дБ, SSIM з 0,48 до 0,78). p2 яскравість не змінює, тому на темних фото PSNR майже не росте.

Стадія clahe у p1 потрібна лише для темних фото. На нормально освітлених вона змінює яскравість, і PSNR падає: за шуму sigma = 10 після bilateral 35,3 дБ, а після clahe 24,0 дБ.

gray_world гірше працює на фото з природно «теплими» або кольоровими фонами: на gauss_10 кореляція між нерівністю каналів оригіналу і приростом PSNR дорівнює -0,67. Через це тест-кейс p2 на gauss_10 пройдено лише на 75 зображеннях з 100.

Швидкість (середній час стадії на зображення 160x160): bilateral 21 мс, clahe 2 мс, unsharp 6 мс, gray_world 1 мс, pyramid 8 мс, butterworth 9 мс.
